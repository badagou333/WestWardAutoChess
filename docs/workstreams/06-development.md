## 2026-10-09 攻位保留条件修正（讨论提案，未实施）

- 更新时间/范围：2026-10-09。负责人指出“敌人移动后旧攻位仍可用就继续走”会继续追远处旧攻位。本轮基线`0273f54`、Local干净、fetch后0/0，只核当前路径/缓存条件及已记录棍僧证据，修改本工作流；不改代码、运行游戏或查看媒体。以下修正此前方案表述，不自行确认新算法或玩法。
- 修正原则：追击意图持续指向敌人，攻位是当前局面下的临时结果。每次可安全发段的决策点，以同一最新占用/时间快照重评整个当前射程攻位集合，比较首次进入有效射程的预计时间；旧攻位仍合法仅有参选资格，不锁定终点。其他攻位完整代价更低就改选，只有与当前最佳同成本的旧有效路线才享稳定优先。旧路线也应截断到首次满足当前射程的格来评分/执行，不能要求走完旧终点后才停。
- 动态接战：落格后当前位置已满足真实射程，就立即驻留并按原冷却攻击。条件示例：棍僧能合法到(5,2)，E1届时已真实在(6,2)，应就在(5,2)接战，不为了原攻位继续向上。只完成已发的0.50秒格段，未执行尾部可重评；不在半格转向，也不拿敌方预约终点作攻击目标。重新评估所有攻位仍使用完整路线/等待成本，不能变成每步仅贪心缩曼哈顿距离。
- 已实现与剩余问题分开：当前_path已以整个射程集合为结束条件；近战落格重算fresh，严格短于有效缓存便替换，可攻时驻留。因此“重评攻位/严格短路替换”不能冒称全是新修复。原1.008秒(4,2)/狼当前(7,2)快照中，先上/先右完整路径均4步，旧终点当时已失效；直接向上原因仍是固定平局顺序及把动态占用当静态墙，不能改写成仅因死保有效旧攻位。仍需验证含等待的时间评价、新等成本路线较早接近当前目标及交通协调，不承诺未知移动目标零折返。
- 验证/待总控同步/下一步：新增必要验收是“旧终点仍合法且旧路可走，但另一攻位完整时间严格更低时确实改选”，以及“缓存路径途中更早进入当前射程立即停步”；原旧终点失效的录屏快照不能替代这两项。同时用当前同速初阵、移动目标/多次变化、等成本稳定、必要绕障及完整段安全做动态对照。本轮仅修正可复用方案，无新运行成绩或代码；下方相关方案段已同步纠正，按持续授权提交推送本工作流，权威玩法仍由01/00统一维护。

## 2026-10-09 同速后的路线规划方案（讨论提案，未实施）

- 更新时间/范围：2026-10-09。负责人要求统一时间后重新梳理路线规划；基线`e20c995`，Local干净、fetch后HEAD/origin0/0。本轮核当前规划/近战/执行链路、已归档同速证据及原作者资料，形成以下提案；仅修改本工作流，不跑新游戏、不查看媒体、不改代码/01/全局。已完成的0.50秒统一速度与本提案的寻路重构分别记录。
- 当前条件/问题：10移动演员均0.50秒/格，但攻击收招、格段完成与请求时刻各异，不能把动作强行当成同步半秒轮。当前`_path/route_valid`仍把全部当前格与目的预约视为全程静态障碍，`_target_legal`又把同一瞬间的空路径直接作为失效；逐演员_brain立即发段使后来者看到变化后的预约。同速尚未改变这些决策关系，也未证明棍僧回转消失。
- 推荐算法/模块：采用短窗口时空协作寻路（CA*/WHCA*思路）的可对照候选。作战层沿现行近远程规则提供目标及其**当前逻辑格**对应的攻位集合；路线层用空间距离表与时空搜索产生Move/Wait/Partial/Reached或结构无路结果；交通协调层在同一实际快照收集请求、按稳定顺序规划临时占用并统一批准第一格段；执行层用原完整格段和真实射程结算。候选路线可供敌我移动单位共用，但不自动把选敌的既有路径成本/合法旧锁策略改成另一套时间优先选敌，狐火追旧敌问题仍属独立作战规则。
- 时间/预约模型：共用原1/120秒模拟tick，每个已发格段固定60tick；保留实际源、目的及边的整段占用，完成后目的格继续被角色占据。未来路线为可撤回的协调计划，已发格段为执行承诺；只提交下一段。起步须再次通过真实占用校验，未实际释放的源格不能提前进入；角色未承诺离开时不假定未来会腾空。交通可使用已决定的活动时间用于防撞，攻位始终来自敌人当前格，不能借预约终点预测攻击或截击。
- 成本/部分路径：统一比较窗口内移动和等待耗时，并用忽略可移动交通、保固定障碍的空间最短距离估计窗口外剩余耗时；窗口有限时只返回可推进前缀，不能把未到达远处攻位判作无路。0.10秒后有实际活动释放的源格，可比较等待0.10＋走0.50与绕三格1.50，但等待需依已发生的活动，不能据此推断预约目的格也会释放。优先优化接近当前攻位的时间估计，不声称知道移动敌人未来真正接战时刻或获得全局最优。理论参考：[Silver作者章节的Limiting the Search Depth / Terminal Node](https://davidstarsilver.wordpress.com/wp-content/uploads/2025/04/cooperative-pathefac81nding.-d.-silver.-ai-game-programming-wisdom-3.pdf)；具体战斗适配为本项目提案。
- 攻位/路线稳定（经负责人追问修正）：能在当前位置攻击时驻留。每个安全移动决策点重评全部当前射程攻位及其完整路线/等待代价；旧攻位仍合法不构成继续走的充分条件，只在与最新最佳同成本时保旧有效前缀。旧路径途中已满足当前射程就截断，目标移动后有更低代价的攻位即改选。没有有效旧路线时，等成本候选优先较早接近目标当前格，再用稳定tie，作为通用路线目标而非坐标特判；完整时间成本仍在方向偏好之前，允许有必要的侧移/后退。对棍僧旧快照期望先到(5,2)，但候选应按新同速真实时序验证，不能以旧异速快照或静态首步算动态修复通过。
- 抢格/阻塞：优先级按未获准移动需求的等待年龄及稳定ID，年龄用模拟时间且不因SCAN/重规划清零；已执行段不可抢占，同一时段只批准一个格段，对向交换也禁止。其他请求在同一协调表上重新比较等待与备选路线。识别循环阻塞，允许有限重排或撤回未执行计划重试；只有实际允许移动且有合法空间的角色可协调让位，唐僧/药灵/不可中断攻击不强行让路。排序只是公平规则，不能单独保证无死锁；无合法侧让空间时明确保留阻塞状态，不能穿人或超时宣告成功。
- 失败语义/触发：明确区分窗口只得部分路线、本轮冲突/短时占用、固定障碍结构无路。前两者保目标/意图并返回推进或等待，只有结构无路/目标失效才支持相应重选；不把“暂时走不动”复用为空路径清目标。重算由目标格/生死、占用活动完成或撤销、路线失效及正常规划刷新触发，移动中只更新未执行尾部。已有射程内其他敌人是否优先于追旧锁，仍需另定作战规则，寻路器不代替决定。
- 取舍/验证/待总控同步：同速降低时空计算复杂度，但PIBT原同步模型与轮转/腾格要求仍不等于当前双端整段占用，故不直接移植；依据[PIBT原论文§3—4](https://www.ijcai.org/proceedings/2019/0076.pdf)，不采用其必达保证。推荐按“空间距离＋时空占用/搜索纯模块 → 同一快照调度与作战接入 → 同速七初阵全12AI对照 → 07独立复验”实施。验收除实际战果/原伤害攻速/速度外，记录等待缘由、攻位改动、路线替换、无必要回退和规划耗时；覆盖短活动等待优于绕行、异步腾格、同格/对向、多单位互堵、固定驻留、目标移动/死亡与窗口外远目标。窗口长度、有限回退预算及新路线tie的确切定义待候选验证，不自行写进确认版。本轮仅方案可复用结论和文档差异检查，没有新规则确认或程序测试成绩；按持续授权提交推送本工作流。
