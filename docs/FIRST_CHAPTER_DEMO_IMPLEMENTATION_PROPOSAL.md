# 第一章 Demo 程序实施方案（待审提案）

更新时间：2026-09-20
维护职责：`06｜程序开发`
状态：负责人已认可 A～D 推荐选项，实施进度见 `docs/workstreams/06-development.md`；具体参数仍为测试值，不替代 `docs/CONFIRMED_GAME_DESIGN.md`

## 1. 目标与范围

本轮目标是尽快得到一个可以真实判断“商店、布阵、合成与战斗表现是否形成完整体验”的主 Demo，同时保留后续扩展为前三难纵向切片和第一章 7 难的结构边界。

推荐采用两级交付：

1. **最小可玩版本（本轮优先）**：把六角色动作与表现能力接入现有主 Demo 的商店、候选区、布阵和单场四波流程。
2. **下一阶段纵向切片**：在同一底座上增加第一章第 1～3 难、章节经济、失败回退、熊山君解锁和最小自动存档。

本轮不把第 4～7 难、正式配色应用、动画精修、完整技能 VFX、完整剧情和最终数值平衡作为前置条件。

## 2. 历史状态与最新交接

`docs/PROJECT_STATE.md` 与本工作流旧记录仍以“单战 Demo、美术待接入”为主，是较早的全局摘要。2026-09-20 的最新可用能力以 `docs/workstreams/05-art-ui.md` 和 `godot-demo/art/reviews/six-role-battle/README.md` 为准：

- 护寺棍僧、山野猎户、山雀精、药灵童子、狐火小妖和熊山君已经有可运行的基础动作素材。
- 三名近战角色已经有连续攻击收势；狐火、药灵和山雀已经有施法过渡；棍僧步态完成垂直接地修正。
- 独立六角色单场试玩已经实现走格、寻敌、攻击、治疗、投射物、退场、暂停、1×/2×和脚底排序。
- 专项测试已覆盖 30/60/120 FPS 一致性、发射与命中同步、远程和治疗抵达后单次结算、死亡目标取消及暂停冻结。
- 主 Demo 的商店、候选区、拖放布阵、自动三合一、人口、四波、战利品与星级结算仍使用旧角色图集和即时伤害逻辑。
- 六角色试玩是独立美术试验场景，尚未进入主 Demo；其中属性、飞行时间、普通受击规则和动作时序仍是试验参数。

因此，当前主要缺口不是继续制作另一套动作系统，而是将已验证的表现能力抽成可复用运行时模块，并接入主 Demo 已有的经营与四波流程。

## 3. 推荐的最小可玩版本

### 3.1 玩家可见闭环

最小版本保留现有主 Demo 的入口和操作：

1. 从商店购买五名初始英雄。
2. 在候选区完成购买、出售、合成和合成锁操作。
3. 将英雄拖到 5×7 棋盘并开始战斗。
4. 经历四波敌人，最后一波面对熊山君。
5. 使用暂停和 1×/2×观察动作、命中、治疗和退场。
6. 根据唐僧剩余生命结算星级和战利品，胜利或失败后可以重新体验。

首个版本仍是一场四波战斗，不宣称已经完成第一章 7 难。其作用是先把正式角色表现和主 Demo 核心循环合并为一个稳定版本。

### 3.2 角色与旧配置映射

| --- | --- | --- | --- | --- |

| `wild_hunter` | 山野猎户 | `rabbit/deer` 的近战输出职责 | 快速近战；猎犬延后 | 数值与技能实现为提案 |
| `sparrow_spirit` | 山雀精 | `crane` 的远程输出职责 | 羽尖发射单体投射物 | 数值、投射物语义为提案 |
| `herbal_spirit_child` | 药灵童子 | 旧 `ox` 的治疗代码思路 | 治疗最低生命比例的英雄或唐僧 | 目标规则已确认，数值为提案 |

### 3.3 技能范围建议

为优先验证完整 Demo，本轮不声称已经实现所有确认版技能：

- 保留普通攻击、远程投射、药灵治疗和狐火小范围伤害，足以体现五个基础职责。
- 护寺棍僧的护盾、山野猎户的猎犬、山雀的安全距离增益、熊山君完整三技能，排到主循环稳定后的独立功能批次。
- 商店信息面板对尚未实现的正式技能明确标注“后续实现”；不得用临时行为冒充确认版技能。
- 二星、三星继续保留合成与基础属性倍率，用于验证经营闭环；新增技能暂不实现。

以上为速度优先的实现提案，需要负责人确认。若要求首个版本必须体现全部一星技能，预计会增加召唤物、护盾、范围选点和 Boss 状态机工作量，并推迟主 Demo 合并完成时间。

### 3.4 可扩展框架

不进行一次性重写，而是从现有 `game.gd` 渐进拆分以下边界：

```text
scripts/
├── data/          # 单位、关卡、波次与临时测试数值
├── presentation/  # 动作清单、图集、发射点、命中反馈和音效接口
├── combat/        # 攻击请求、释放、投射物、命中/治疗单次结算
├── state/         # 后续章节状态与存档快照
└── game.gd        # 组合商店、布阵、波次和战斗系统
```

关键原则：

- 玩法身份、数值、图片路径和动作时序分离，换图或改动作不改战斗规则。
- 单位模型继续承载星级、商店、棋盘和生命数据；角色表现由可复用的 `CharacterPresentation` 子节点处理。
- 主 Demo 和独立六角色试玩共用运行时表现模块；审核场景不再复制一份正式战斗逻辑。
- 攻击通过唯一动作序号进入统一结算队列，近战在释放点结算，投射物与治疗在抵达时结算。
- 章节、关卡和存档接口先留边界，但本轮不提前实现未确认的 7 难内容。

## 4. 分批实施步骤

### 第 1 批：抽取角色表现适配层

涉及模块：六角色 `actor.gd`、`motion.gd`、各角色 manifest、新建 `scripts/presentation/`，以及 `unit.gd` / `enemy.gd` 的表现委托接口。

工作内容：

- 将素材加载、脚底锚点、朝向翻转、动作时序、发射点、深度排序、受击闪光和退场淡出抽成主工程可复用模块。
- 保留独立试玩作为视觉回归入口，但改为引用同一运行时模块。
- 不改商店、技能数值和波次规则。

可试玩成果：主 Demo 中旧商店和四波规则不变，但已购买/上阵单位可以显示新角色动作；独立六角色试玩仍能运行。

依赖：当前六角色 manifest 与 motion 素材。配色和精修不阻塞。

### 第 2 批：接入统一攻击与反馈流水线

涉及模块：新建 `scripts/combat/`，调整 `game.gd`、`unit.gd`、`enemy.gd`，复用独立试玩的 strikes、missiles、marks 和固定小步长逻辑。

工作内容：

- 将主 Demo 的“播放攻击后立即扣血”改为“动作释放点/投射物抵达后结算”。
- 每次攻击生成唯一序号；取消死亡目标和过期动作，保证伤害/治疗只发生一次。
- 统一暂停、倍速、动作、波次、移动、投射物和反馈时钟。
- 将已有命中闪光、短顿帧和圆环提示迁入共用模块。

可试玩成果：四波仍使用旧数据，但攻击画面与伤害时刻同步，远程和治疗可观察到完整飞行过程，暂停与倍速一致生效。

依赖：第 1 批表现适配层。

### 第 3 批：正式身份接入商店、布阵和合成

涉及模块：单位数据、商店池、信息面板、初始商店、合成测试和主 Demo 自动检查。

工作内容：

- 商店与候选区改用五名正式身份 ID，全部按白色 1 费处理。
- 保留 3 个同名同星自动合成、单体合成锁、最高三星、出售规则和人口限制。
- 迁移 UI 名称、图标与属性读取；测试不再依赖旧 `rabbit/crane/ox` 名称。
- 使用专门测试数据验证三合一，不要求首屏商店为了测试而固定出现三张同卡。

可试玩成果：玩家可以在主 Demo 中招募、合成、拖放并使用五名正式英雄。

依赖：第 1 批；可与第 2 批后半段串行完成，避免同时修改 `game.gd`。

### 第 4 批：四波正式角色整合版

涉及模块：波次数据、熊山君敌方接入、最小职责技能、胜败和重开流程。

工作内容：

- 前三波继续复用现有灰鼠、山猪和狼类占位素材与测试数值；第 4 波用熊山君替换旧虎先锋。
- 接入药灵治疗和狐火小范围伤害；其余角色先以职责化普攻运行。
- 清理胜利文案中的旧角色名，所有临时数值与未实现技能标注为 Demo 提案。
- 保证失败不结算战利品、胜利按唐僧血量评星、重开完整复位。

可试玩成果：得到本轮目标版本——商店、布阵、合成、六角色动作和四波 Boss 战统一在主 Demo 内运行。

依赖：第 1～3 批。第 4～7 难、配色和美术精修均不依赖。

### 第 5 批：最小音效、回归与交付包装

涉及模块：音效管理、设置开关、自动测试、Windows/Mac 启动说明。

工作内容：

- 仓库当前没有 `.wav`、`.ogg` 或 `.mp3`，因此首轮新增可替换的自制短占位音效：近战命中、远程发射/命中、治疗、退场和 UI 点击。
- 所有音效通过角色/事件 ID 路由，不把文件路径写死在技能逻辑中；提供总开关和音量。
- 跑主 Demo 冒烟、四波、六角色专项以及新增整合测试；进行一次有窗口试玩。
- 可选轻微震屏只用于熊山君重击或唐僧重伤，默认关闭或由配置开关控制，不作为交付门槛。

可试玩成果：可直接交给负责人体验的主 Demo 整合包。

依赖：第 4 批；震屏无前置价值，可随时删除或延期。

### 后续批：前三难纵向切片

在主 Demo 整合通过后，再增加数据驱动的章节—关卡—波次结构、前三难、章节经济、失败回退、熊山君解锁和最小自动存档。届时主要扩展数据与状态层，不重做角色表现和攻击结算。

## 5. 最小打击反馈方案

### 5.1 已有能力，直接复用

- 受击短闪光和轻微水平回弹。
- 近战出手后约 35ms 的攻击者顿帧，以及目标约 25ms 的短停顿。
- 独立远程/治疗投射物、发射点随手掌或羽尖变化、死亡目标安全取消。
- 命中/治疗圆环标记。
- 受击不频繁重置正在播放的移动或攻击动作。

以上能力已经过专项测试，不应在主 Demo 中另写一套 Tween 式反馈。

### 5.2 建议补充

- 将现有圆环改造成极简的缩放+淡出：伤害暖色、治疗绿色；不新增复杂粒子系统。
- 普通命中只组合“闪光 + 小回弹 + 短顿帧 + 小圆环 + 音效”，控制噪声。
- 熊山君重击可以增加更大的地面环；其技能范围尚未确认，因此首版只作视觉强调，不改变伤害范围。
- 基础音效使用可替换占位资源，后续正式音效只替换事件映射。
- 震屏建议为 1～2 像素、80～120ms 的低幅效果，仅在重击时启用；提供开关，若影响拖放 UI 或画面舒适度则延期。

## 6. 验收标准

### 6.1 暂停、倍速和帧率一致性

- 暂停后，波次倒计时、移动、动作时钟、投射物、命中标记、生命变化和治疗全部冻结；UI 按钮仍可操作。
- 1×/2×切换不能跳过攻击释放点或让同一动作重复结算。
- 在 30/60/120 FPS 固定步进测试中，攻击请求、投射物、命中、治疗、取消和最终胜败计数一致。
- 2×的模拟结果与 1×一致，实际等待时间约为一半；允许极小浮点时间误差，不允许结果差异。

### 6.2 伤害与治疗单次结算

- 近战攻击在动作释放点结算一次，不能在点击/起手时提前扣血。
- 远程攻击和治疗在投射物抵达时结算一次，不能在发射和抵达各结算一次。
- 目标死亡、战斗结束或攻击序号失效时，未完成事件必须取消。
- 药灵只选择当前确实受伤且存活的最低生命比例目标；无受伤目标时不空放治疗。
- 受击反馈不能重置正在进行的攻击，死亡必须中断后续伤害并进入退场。

### 6.3 商店、合成和布阵

- 商店只从当前最小版本的五名白色 1 费英雄中抽取；每次展示 5 个位置，重复出现合法。
- 金币不足、候选区满、战斗中购买/出售/刷新必须被正确阻止。
- 三名同 ID、同星、未锁定英雄恰好合成一个高一星英雄；消耗数量和金币价值正确，最高三星。
- 被锁定英雄不参与自动合成；解除锁定后立即重新检查。
- 星级变化不丢失角色表现、棋盘/候选区位置和选中状态；人口上限仍按上场英雄数量计算。
- 五名正式英雄均能从商店进入候选区、上棋盘、移动、攻击/治疗、受击和退场。

### 6.4 四波与胜败

- 每波按配置预告并生成，上一波存活敌人清空后才进入下一波。
- 第 4 波熊山君实际登场并可被击败；旧虎先锋名称和解锁文案不再残留。
- 唐僧死亡立即失败，未结算战利品不进入金币。
- 胜利按战斗结束时唐僧生命计算 1～3 星，并按现有 80%/90%/100%规则结算。
- 暂停、2×和不同帧率下，默认测试阵容的最终胜败和总战利品一致。
- 重开后敌人、投射物、临时标记、战利品、暂停和倍速全部复位，商店与阵容按本轮单战 Demo 既定重开规则恢复。

## 7. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 直接把美术试玩 `actor.gd` 当正式单位模型 | 商店、星级、拖放和战斗状态混在一起，后续难扩展 | 只抽表现组件，玩法模型继续由 `unit.gd`/`enemy.gd` 或后续数据模型承载 |
| 同时重构商店、战斗、章节和存档 | 回归范围过大，难以定位问题 | 按五批串行，每批保持可试玩并通过旧测试 |
| 复制六角色试玩逻辑到主 Demo | 两套系统继续漂移 | 让独立试玩和主 Demo 共用 presentation/combat 模块 |
| 动作时序与即时伤害并存 | 提前扣血、重复结算、倍速漏帧 | 统一动作序号与攻击结算队列，固定最大小步长 |
| 旧占位 ID 泄漏到新数据 | 后续存档与内容扩展需要再次迁移 | 新数据只写稳定正式 ID，旧 ID 仅保留显式兼容表 |
| 把试验数值误认为正式平衡 | 形成错误基线 | 数据文件和 UI 标记 Demo 提案；不写入确认版设计 |
| 过早补复杂 VFX/震屏/配色 | 推迟闭环交付 | 只复用已有反馈，音效最小化，震屏可选，精修延期 |

## 8. 需要负责人决定的少量问题

### A. 首个交付是否先做单场四波整合版

- **推荐：是。** 先把正式角色表现接入现有主 Demo，完成后再扩前三难。
- 备选：直接做前三难，会同时引入章节状态、关卡数据、失败回退和存档，首个可玩成果更晚。

### B. 首个版本的技能深度

- **推荐：职责化最小行为。** 保留普通攻击、药灵治疗、狐火小范围伤害；护盾、猎犬、山雀增益和熊山君完整技能随后逐项实现。
- 备选：首个版本完成全部一星能力，体验更接近正式设计，但会明显扩大实现和测试范围。

### C. 旧普通敌人与测试波次是否暂时保留

- **推荐：保留前三波的灰鼠、山猪和狼类占位配置，只将最终 Boss 替换为熊山君。** 这些数据继续标记为单战测试配置，不等于第一章正式波次。
- 备选：立即切换第一章前三难数据，会把本轮目标从“整合主 Demo”扩大到章节流程。

### D. 最小音效来源与震屏
