## 记录规则

- 本文记录跨领域决策的变更轨迹，不替代详细设计文档。
- 玩法与范围的当前有效版本以 `docs/CONFIRMED_GAME_DESIGN.md` 为准。
- 只有项目负责人明确确认的内容才能标记为“已确认”。
- 专项聊天发现的新确认事项先写入自己的工作流文件，由总控登记并链接到权威文档。
- 决策编号格式为 `D-YYYYMMDD-NNN`；修改旧决定时保留旧记录并注明替代关系。

## 决策状态

- `已确认`：可以作为后续设计和开发基线。
- `试验中`：允许实现或测试，但不能视为最终方案。
- `已替代`：历史决定，已由新决定取代。
- `已否决`：明确不采用，除非项目负责人重新开启讨论。

### D-20260902-002｜采用轻量启动与上下文控制

- 状态：已确认
- 领域：项目协作
- 决定：新聊天默认只读取文本入口，不自动打开媒体资产；纯 Git 与明确范围的文件整理使用快速通道，只加载完成任务所需的最小上下文。视觉任务按需打开最小图片集合，机械任务尽量合并步骤并优先使用低推理强度。
- 原因：美术聊天曾因初始化阶段批量查看图片、重复加载文档并以高推理强度执行机械任务，导致新聊天迅速增长到约 9 万输入 tokens，简单操作耗时超过 30 分钟。
- 影响文件：`AGENTS.md`
- 确认人：项目负责人
- 确认日期：2026-09-02

### D-20260907-003｜以 Gitee 作为跨机器同步基线

- 状态：已确认
- 领域：项目协作
- 决定：Gitee 的 `origin/master` 是本项目跨机器共享代码、资产、文档和项目记忆的权威基线。新机器从 Gitee 克隆仓库并以仓库根目录建立 Codex 本地项目；每批修改完成后必须提交并推送到 Gitee。
- 原因：项目会在多台机器上继续开发，而不同机器和不同 Codex 任务不能依赖聊天记录或未提交的本地文件同步状态。
- 影响文件：`README.md`、`docs/DEVELOPMENT_HANDOFF.md`、`AGENTS.md`
- 确认人：项目负责人
- 确认日期：2026-09-07
