## ① 运行逻辑（07 自写 `qa07_mirror_logic.gd`，100 项 / 0 失败）

用生产场景 `main.tscn`，关闭自动 `_process`，以固定步长手动推进，保证结果确定可复现。

- **两个朝向各自验证：**
  - **完整播放：** 每一步的帧索引都等于按 PTS 查表的结果，且不倒退。WAV 在第一个 ≥0.405 秒的步长开始播放。到 T 时进入 ENDED，停在 index97，elapsed 被钳在 T，此时无声。之后再推进 2 秒，仍保持 ENDED、index97、无声，不会循环。播放和重播按钮的启用/禁用状态正确。
  - **重播：** 结束后重播会清零并重新触发声音事件。声音播放中重播，会立即停掉旧声音，到 0.405 秒后使用新的 playback。
  - **切向：** 分别用按钮信号、数字键 1/2（引擎 `Input.parse_input_event` 走 `_unhandled_key_input`）和 API 三种方式切向。切换前后 elapsed、state、audio_event_handled、正在播放的 WAV playback 对象及播放位置、帧索引都不变，按钮按下状态与朝向一致。重复选择同一朝向不产生任何变化，0、3 等非法朝向值被忽略。播放中多次切向后，仍按时结束在 97 且无声。
  - **其他状态下切向：** ENDED 状态下切向不会出声。0.405 秒之前切向，不会提前触发也不会吞掉声音事件。INSPECTION（审帧）下切向保持 31 号帧且无声。
- **全局：** 所有切换之后，98 个纹理对象和 WAV stream 对象的实例 ID 都没有变化（同源复用，没有重新加载）。镜像状态下从场景树移除节点后，WAV 停止。
- **几何：** 两个朝向下 `source_to_world(foot_reference)` 都等于 (720,441)。205 个源点（含四角、脚点和 200 个随机点）在镜像下满足 x′=1440−x、y 不变。

## ② / ⑤ 对称与 1/255 残差（07 自写 `qa07_mirror_render.gd`，7 项 / 0 失败）

- **比较方式：** 在纯色审阅底上，98 个源索引两向各渲染一次。比较范围是 UI 以下的整个舞台（y 140–809，x 0–1439，比作者的 560–879×260–499 更大），比较原向 (x,y) 与镜像 (1439−x,y)。
- **默认过滤：** 19 个索引共 49 个像素不同，差值全部恰好是 1/255，最大也是 1/255。出现差异的索引在 31–55 之间，单个索引最多 6 像素。这与作者报告的数字完全一致，范围扩大后也没有新增差异。每个索引的镜像图与未翻转图至少有 6408 个像素不同，说明确实发生了翻转；每帧都有至少 5610 个角色像素。
- **对照 a（确定性）：** 原向同一帧连续渲染两次，0 像素差。
- **对照 b（最近邻过滤）：** 把场景切到 `TEXTURE_FILTER_NEAREST` 后重新扫描全部 98 帧，**0 个索引、0 个像素不同**。这说明两向采样的源纹素位置完全对称：几何、帧选择和脚点都没有偏差。残差只来自双线性插值的浮点舍入。按数学推导，像素中心 x+0.5 与 1439.5−x 映射到同一个源坐标 475+(x+0.5−720)/0.21。
- **判断：作者的解释成立。** 1/255 残差人眼不可分辨，不属于必修。作者把对称门限定为“逐位相同”，因此作者脚本退出码为 1。这条门限不适合作为 GPU 双线性下的验收门限，建议以后改为“NEAREST 下逐位相同，且默认过滤下 ≤1/255”。
- **棋盘与脚格：** 棋盘视图下两向对比，棋盘远端点和角色画布外的 5 个点像素完全相同，说明棋盘和格子不随朝向翻转。另附 index0 两向脚点区域的裁片各一张（`render/crop-*.png`），只作取证，不代替 05 的视觉复核。
- **素材：** `git diff 2edba55..98fd390` 显示 `art/` 和 `showcase.json` 没有改动。verify_assets（候选取 `git -c core.autocrlf=false archive` 的原字节）结果 1209/0：101 件复制素材、98 条 PNG 记录、manifest SHA `fd1ae832…`、WAV 和 PCM 都校验通过，98 张 PNG、manifest 和 WAV 与候选逐字节相同。

### QA-20261110-C03M-01（P3，非阻塞）：`launch.bat` 不认 `GODOT_BIN` 环境变量

- **位置：** `c03-attack-showcase/launch.bat:23` 的 `set "GODOT_BIN="` 写在“1) 优先使用环境变量 GODOT_BIN”判断之前，用户设置的值在判断前就被清空，脚本头部注释和报错提示中的“办法一”都不会生效。
- **最小复现：** 设置 `GODOT_BIN=C:\software\Godot-4.7.2\Godot_v4.7.2-stable_win64_console.exe`，然后执行 `launch.bat --headless --quit`。预期输出“使用环境变量 GODOT_BIN”并选用 console 版；实际没有这条输出，打印的是 `Godot : …win64.exe`（标准版）。日志见 `logs/launch-bat-godot-bin-override.log`。
- **影响：** 默认安装路径下启动正常。只有引擎不在 PATH 和已知目录中、需要手动指定路径时，用户会被引到错误提示，形成死路。`bear-forehand-showcase/launch.bat:23` 有同样的写法（来源相同，未单独实测）。
- **建议修法（由 06 决定）：** 删除第 23 行，或者先把 `GODOT_BIN` 保存到另一个变量再清空。
