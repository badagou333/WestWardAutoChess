### 播放逻辑（07 `qa07_b04_logic.gd`，53 项 / 0 失败）

- **PTS 查表：** 场景的 `frame_ticks` 等于独立读取的 manifest PTS。84 帧的持续时间是 42 个 768 和 42 个 512（时基 1/15360），合计 53760，即 T＝3.5 秒。
  - 对每一帧检查三个时刻：恰好在自己的 PTS 时显示本帧；PTS 前 1 微秒和前一帧持续时间的中点时，仍显示前一帧。t≥T 时显示 83。
  - 用 1 毫秒采样与固定 24 FPS 查表对比，3500 个采样中有 350 个不同，证明播放不是按固定 FPS 查表。
  - 以 1 毫秒步长从头播放：每一步的索引都等于独立 PTS 查表结果，单调不倒退，84 帧全部出现过。
- **声画同起：** 通过播放按钮信号开始时，显示第 0 帧，WAV 同时开始。原生起播位置与同一 WAV 独立参考在相位 0 起播的位置相同。原生会预填 128 个采样（0.0029 秒），这一点见下文 07 首失。整段只有一个 playback 对象，一直在播。
- **结束：** 到 T 时进入 ENDED，停在 index83，elapsed 等于 T，声音停止。再推进 2 秒仍是 ENDED、83、无声，不循环。播放按钮禁用，重播按钮可用。
- **重播：** 结束后重播从 0 开始，使用新的 playback。声音播放中重播，会替换旧 playback 并回到相位 0。
- **其他状态：** 一次 10 秒的大停顿越过 T，结果仍是 ENDED、83、无声。审帧 35 时无声，之后保持静止；越界的审帧请求被忽略。从场景树移除节点后，WAV 停止。
- **配置可调（临时副本）：**
  - `scale 0.25 / 脚点 (600,400) / mipmaps false`：配置生效，脚点、缩放、纹理有无 mipmap、过滤方式都与配置一致，能播放到 83 且无声。
  - `scale 0.16 / mipmaps false`：同样通过。
  - `scale 0` 和 `scale 1.5`：被拒绝，`ready_to_play=false`，有错误信息，按钮禁用。
  - 默认配置下：脚点为 (720,441)，倍率 0.16，mipmap 开启（过滤方式 `LINEAR_WITH_MIPMAPS`，纹理带 mipmap）。画布在世界中的范围是 (671.52,331.56)–(809.76,453.16)，与作者记录一致。

### 作者“首次播放探针 4 项失败是探针计数期望错”：成立

- `realtime-first.json` 与修正后的 `realtime.json` 记录的实际观测一致。4 段都是事件转换 1 次、播放实例 1 个；两次完整播放的结束状态都是 ended、83；退出后都已移出混音。只有观测到的不同帧数随刷新不同（81/73 和 81/72）。
- 失败断言是 “plays exactly one WAV playback … never retriggered”。现版本探针的条件是 `handled_transitions == 1`，注释说明偏移 0 的声音在按下按钮时已经处理，所以首个样本必然记一次转换。首跑报错的原因与“期望 0 次”的说法吻合。
- 07 自己的逻辑探针也独立确认：每段只有一个 playback，没有重复触发。
- 限制：`showcase.gd` 和探针都只在 939fd1b 这一个提交里，git 历史无法单独证明首跑和终跑之间生产代码没有变化。这个结论依据的是两次运行数据的一致性和作者的说明。

### 内存粗测（非必修）

- **读数：** `RENDER_TEXTURE_MEM_USED` 在 mipmap 开和关时都约为 **287 MB**，静态内存约 78 MB（解码后 Image 已释放）。
- **对照：** 07 加了一个隔离对照（`qa07_b04_memcheck.gd`）：10 张帧，不论带不带 mipmap，监视器读数都是 33.4 MB/10 张。说明在 Compatibility 渲染器下，这个监视器不区分纹理是否带 mipmap。
- **结论：** 作者估算的“约 220MB，加 mipmap 约 290MB”无法用引擎监视器证实。真实显存分配需要驱动级工具，本批没有测。
