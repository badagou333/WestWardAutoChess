## 交付与接入

`carry-animations.json` 仅 9,073 字节，SHA-256：`342400fec4c0d6c731fbcd3b8f853208633bfe6e1cad0515b0ebe6bae832bdb7`。

- 动作：`CarryIdle` 3 秒、`CarryRun` 2/3 秒。
- 六骨：`upper_arm.L/R`、`forearm.L/R`、`hand.L/R`。不替换 clavicle 或其他骨骼。
- `clips → 动作名 → tracks` 包含 `bone`、glTF 原 `path`（translation / rotation / scale）、`times`、`values`、`interpolation`。每动作 18 个通道。
- **值是 glTF 父节点局部绝对 TRS，旋转为 xyzw；不是 Blender Euler，也不是再乘一次 rest 的增量。** 坐标与已用 GLB 动画相同，模型 Y-up、+Z 前向。应复制原 Idle / Run 后只替换这些骨的对应轨道。
- 原 Blender 帧 1 在 glTF 中是 1/30 秒，造成导入器显示原时长 3.033333 / 0.7。本 JSON 已减去 `source_time_offset=1/30`，从 0 播至真实端点；保留原非手臂轨道时也要去掉这段 lead-in，并按原始 1/30 秒采样建立新 0 时刻，不把 Godot 添加的合成 t=0 直接移成负数。
- 手臂相对于胸保持稳定托举；实际呼吸、身体转动和奔跑起伏继承原动作。官方导出器将恒定手臂局部通道优化成首末两键，这是有效压缩，不是缺失腿部动画。

## 火球位置

JSON 的 `palm_offsets` 已给双手骨局部掌心：`(0, 0.037804659, 0)`。分别用 `hand.L/R` 当前骨姿态变换到模型空间，取中点后沿模型上方加 `0.075`。最后通过角色整体变换到世界，缩放只乘一次。

核心建议半径 `0.07～0.077` 模型单位；火尖相对球心高度建议不超过 `0.10`，具体仍以实际镜头/VFX避脸检查为准。这些是同一原尺寸模型的数值；角色缩放 1.65 时，相应世界上移约 0.124，核心半径约 0.116～0.127。

两掌向内上方围成浅托，手腕抬至上腹/下胸，肘低于肩并略离躯干；球前置，面部轮廓保留。不要把火球重新绑到角色原点或单手腕，否则会丢失双手承托关系。

## 制作与验证

`build_carry.py` 打开相邻 `hunyuan_board_actor_v1/foxfire-board-actor.blend`，复制 Idle / Run，在随胸运动的坐标系内做双骨臂求解与掌心旋转，然后调用 Blender 官方 glTF 导出器生成**临时纯骨架动作**，提取所需通道。临时 GLB 在 `/private/tmp/foxfire-carry-actions.glb`，没有网格、贴图或完整模型副本进入本目录。

- 原动作全部曲线保持；新动作的所有非手臂曲线逐项一致。111 个实际蒙皮采样的两动作首末网格误差均 0，最低顶点均高于地面。
- 实际掌面法向向上分量：Idle 最低约 0.9786，Run 最低约 0.9804；不是把掌背当掌心。左右略向内，手爪与球下缘都保留可见轮廓。
- 作者查看最终 Idle 前/侧与 Run 四个关键姿势的前/侧渲染，所查看姿势未见手臂穿胸、双手互穿或明显袖子反折。该判断不覆盖所有时刻的全身自碰，也不代替 Godot 起停混合、VFX 和镜头验收。
- `build-report.json` 保存来源 SHA、曲线检查、循环误差和逐帧关节/掌面数据；`carry-*.png` 是真实 Blender 网格渲染，不是引擎截图。橙色实心球仅为托举关系的检查道具，未导出，真正火球由引擎特效制作。
- 手指未增加独立骨骼，不能单独卷曲抓握；宽袖和衣摆仍沿用现有蒙皮，不宣称布料模拟。已有 Idle / Run 的 Kenney CC0 来源与用户模型许可边界继续见相邻资产 README，未新增外部资产。
