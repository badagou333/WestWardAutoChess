# 熊山君正手攻击：限定试验素材

状态：**待视觉审查，不是正式可用或完整动作**。这是从现有视频选帧的单方向试验；未改动原视频、原画或现有游戏资产，也未调用生图、生视频服务。此目录 `.gdignore`，仅供人工审核及后续明确复制到专用试验目录，不能直接当作 Godot 已接入成果。

## 来源与选帧

视频：`../bear_lord_video_attack_v1/forehand-7499-short-windup-v2.mp4`，960×960，解码得到 96 帧；视频含原平台生成标记。原视频可变帧率，时间戳来自 FFmpeg `showinfo`。`manifest.json` 给出每帧一基源帧序号、源时间、试验时间和时长，`frame-verification.json` 给出各帧散列与画布边界检查。

源视频第 52、53 帧（分别位于 1.633333、1.666667 秒）棍头真实出画，**不符合原素材边界检查要求**；这两帧被舍弃，所选第 51 帧直接跳到第 54 帧。见 `source-edge-evidence.jpg`；这意味着挥击过程中存在缺失和跳变，无法证明挥击连续完整。其余帧也有选帧跳跃；没有补画或通过扩大画布伪装出画内容。

## 清理和排版

原视频为浅色不透明背景，使用 FFmpeg 浅色键及连通区域的形态学遮罩做试验抠像；主体 RGB 未重新绘制或调色，但键控、透明度、缩放与边缘混色会影响局部像素。大范围灰色挥击弧因与背景接近，**已删除，未保留原视频特效**。挥击时腿脚被原视频效果覆盖，试验第 10–12 帧有明显白边和发灰，深底尤其明显，尚未达到视觉验收要求。

`finish_frames.py hd` 使用所有帧相同的缩放和平移：输入 960×960，约 0.337662 倍，输出统一 384×320，area 采样；没有逐帧追踪、移动或重绘主体。导出的 PNG 为直通道 RGBA（缩放时内部以预乘通道运算）。每帧外围 4 像素均透明，但这只证明输出画布没有触边，**不证明原片未裁切，也不证明抠图质量合格**。

现有游戏熊山君与该视频在皮毛、护甲及武器姿态上有明显差异，`existing-look-comparison.png` 可查看造型切换。攻击帧和现有待机之间的跳变必须由负责人审看后决定处理，暂未解决。

## 试验接口与待确认时序

- 平铺 `attack_00.png` 至 `attack_19.png`，全部 384×320；`manifest.json` 的 `frames[*].at` 单位为秒，第一帧从 0 秒开始。
- 一个试验动作 0.820 秒；索引 11（第 12 张，来源视频第 54 帧）在 0.389 秒作为**拟定**命中同步点，以适配现有棋盘命中时钟；视觉打击路径缺帧，该同步点并不证明真实接触或打击感合格。
- `foot=[177,213]` 为初始画面双脚中点的人工估计；`feet`、`emission` 和 `scale=1.234` 均为试用参数，须在实际棋盘中确认，不能视为精确判定或承诺不漂移。`source_sign=1`、`source_back=false` 仅定义此试验接口的朝向用途。
- `preview-dark.gif`、`preview-light.gif`、`preview-checker.gif` 为不同背景的循环查看图。GIF 只能以 10 毫秒单位表示帧时长，精确播放以 manifest 为准；对应 `contact-*.jpg` 为逐帧证据。

## 检查结果和未完成项目

使用本机 sprite forge doctor，缺少 `ffprobe`；`video2dsprite.py triage` 因此未能运行，未进行该步骤的门禁检查。原工具 clean 不支持该浅灰白色键，故采用上述有限抠图方法；`finish_frames.py hd` 给出 `needs-visual-review`。验证 20 张同尺寸、非空并检查外围透明；生成深浅底和棋盘预览，但未通过独立视觉验收、实机播放或角色一致性验收。

正式使用前需解决原素材出画与缺失路径、清理挥击白边和腿脚灰影、统一待机及攻击造型，并实际验证动画节奏、锚点、攻击方向、尺寸和打击判定。若需完整挥击，要使用未出画的原始素材或获得用户授权后重新制作，不能声称此试验版已补全。
