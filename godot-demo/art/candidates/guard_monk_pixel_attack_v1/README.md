## 动作与选帧

| 时间 | 帧 | 动作 |
| --- | --- | --- |
| 0.00s | 00 | 近竖直高低手蓄力，对应新图一 |
| 0.16s | 01 | 棍头转向右上，肩肘开始展开 |
| 0.24s | 02 | 进一步向右上加速出手 |
| 0.30s | 03 | 右上伸臂接触，对应新图二 |
| 0.42s | 04 | 双肘回拉、重心回收 |
| 0.57s | 05 | 近竖直回收归位 |
| 0.73s | 00 | 复用同一张蓄力图，0.82s动作结束 |

原生成sheet为8姿势。本轮只采用其第1～6号（按0起算）的六张真实重画帧；原0/7号斜持棍身明显偏长，排除以避免掺入长短棍切换。不是用整个人平移、旋转或程序骨骼摆动代替出手补帧。逐帧取用框、连通主体种子、统一缩放和脚底参考在 `frames_spec.json` 中明确记录，未按4×2平均切图。

## 制作与接口

- 内置imagegen使用三份负责人图片：`inputs/owner_raised_staff.png`、`owner_upward_strike.png` 是动作依据，`owner_detailed_pixel_guard.png` 只约束细节版身份与像素风。完整实发提示词在 [source/PROMPT_UPWARD_ATTACK.txt](source/PROMPT_UPWARD_ATTACK.txt)，原件与输入哈希在 `source/provenance.json`。
- 每帧448×448 RGBA，同一来源缩放0.66；全组共享96种不透明颜色，无抖动、最近邻取样，alpha二值化，透明RGB归零。源图是高分辨率像素风重画，不称为逐格手工绘制或原生448网格生成。
- 脚底参考 `(95,393)` 对齐后侧鞋底支点，允许前腿弓步和重心前移。它不是旧256帧格 `(128,218)` 的兼容接口，不宣称双脚像素锁定或运行接地已验。
- 接触0.30s与0.82s动作时长是本候选预览节奏，**未接实际伤害、攻速或游戏事件**。GIF按10ms粒度编码；本组关键时刻均可精确表达。
- `.gdignore` 隔离整个目录，不进入Godot默认导入/PCK。没有修改现有游戏代码、场景、production、平衡或导出配置。

## 复核与限制

作者及独立视觉复核查看最终接触表：新动作方向、双手持同一根完整直棍、两端金属帽及关键姿势衔接达到可展示门槛，未见新增必修。六帧仍有轻微投影棍长、握位、衣褶与鞋位重画差异；不称严格恒定或全速绝无跳变。独立逐帧结构、GIF解码、输入快照、图集和确定性重建结果见 `validation.json`。

这是一段可播放的独立攻击动画候选。负责人连续观感、其他朝向、移动/受击/退场、运行接地/伤害同步及最终采用仍待后续；不会据此替换现有13帧动画。

## 重建

有Pillow与NumPy的Python可在任意目录执行：

```sh
python3 /path/to/guard_monk_pixel_attack_v1/build_animation.py
```

从仓库保存的原件与显式选帧记录重建全部成品；不保证重新调用生成模型得到同图。重建脚本只提取、对齐、限色和打包已有姿势，不补画肢体。
