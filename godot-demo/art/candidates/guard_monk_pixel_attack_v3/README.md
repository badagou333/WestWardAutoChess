## 本轮修改

内置imagegen只编辑原接触帧，完整提示词见 [source/PROMPT_LOWER_TIP.txt](source/PROMPT_LOWER_TIP.txt)。生成原件为1254²，按最近邻匹配原448²画布，再限到原96色色板、二值alpha，仅将显式多边形区域贴回原图。采用 `body/03_contact_lowered.png` 覆盖本候选的身体id3；未覆盖v1/v2文件。

局部区域包含棍、两手与最小相邻前臂／袖部，并清理旧抬腕位置留下的浅色尖角。最终9675个RGBA像素改变，范围为 `[201,159,443,313]`；掩码外、脸部保护区和下身逐像素保持。掩码、规格、重建和哈希在 `patch_spec.json`、`source/edit_region.png`、`patch_report.json`、`source/provenance.json`。

其他身体姿势未改；新版8个合成阶段中只在三个接触阶段使用覆盖帧，其他阶段与v2逐像素相同。230ms接触、800ms动作＋350ms待机、200～300ms残影与其强度完全沿用v2；FX直接复用v2已拟合PNG，不重画或重新变换。

## 复核与边界

作者与独立前后图复核确认：下压仍是斜出收劲，直棍／双帽和双手握持可辨，前臂贴回未见新缝隙或残片，脸与站位观感保持。独立结构／未改区域／时序／GIF和图集证据见 `validation.json`。仅静态复核，不据此宣称真人连续观感、严格恒定棍长或游戏内命中已通过。

本目录由`.gdignore`隔离，未改游戏、production、数值或导出配置。230ms仍为预览接触时刻，未接伤害。v2已认可的节奏保留，最终末端幅度由负责人体验。

## 后续手部复审

负责人指出显示第2／3／4帧下面那只左手可能反了。作者与独立只读复核放大该局部，并对照 `../guard_monk_pixel_attack_v1/inputs/owner_upward_strike.png` 的下方握手：原参考是从棍下承托、掌侧包握，拇指与手腕内侧的扣合可辨；当前更像朝镜头的大块拳背，掌背和包棍方向与参考不一致，尤其接触姿势。此处确认的是掌背翻转／握法走样的视觉问题，不断言整手已被机械镜像或旋腕在解剖上绝对不可能。

实际需修两张身体姿势：显示第2帧的body2，以及显示第3／4／5帧共同使用的body3覆盖图。后续应局部重画左手的掌指、拇指与腕口连接，沿用既有直棍／握点、末端下压、脸／脚／节奏与残影；不能仅翻转整只手或整个人。本轮未生成修稿、未改PNG或动画。

## 重建

使用带Pillow／NumPy的Python，依次运行本目录 `build_patch.py`、`build_lowered.py`。前者从保存的生成原件重建局部覆盖帧；后者复用仓库内v2打包工具及分层FX，仅替换本候选body3。所有路径相对脚本，不依赖临时附件或工具默认输出目录。
