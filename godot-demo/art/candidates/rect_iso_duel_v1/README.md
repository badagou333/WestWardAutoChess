更新时间：2026-10-18。任务：D-20261018-002，05素材阶段。

本包完成**有限关键姿势素材交接**，不是完整动画包。两角色各有斜前SE、斜后NE的待机、移动A/B、攻击起手/接触，共20张独立透明帧；保留四张生成原图和全部提示词。静态待机的单格摆放、透明合成和四向镜像经作者及独立只读视觉复核通过。棍僧背向、山狼双向步态换相失败，若干攻击足底遮挡；没有将这些问题写成全套通过。尚未运行Godot、未由07验收、未获负责人对新包的观感确认。

## 可用与不可用

以下均指独立原型候选，不能等同正式动画验收。源方向SE/NE分别镜像为SW/NW。

|角色／动作|建议与限制|
|---|---|
|两角色SE/NE待机，4源帧|可用于静态摆放原型。双脚或四爪均可辨，完整可见足端包络落在90%内线内；共8个含镜像显示方向通过静态复核。|
|棍僧SE移动A/B|可用作两张交替腿关键姿势，仍缺经过帧与连续时序验证，不是完整顺滑步态。|
|棍僧NE移动|A/B仍同一腿相位，交替循环失败。原型只建议取A作为有限移动姿势；B保留但不推荐组成循环。|
|山狼SE移动|A可作有限移动姿势；B远侧足端融合，至少一足无法独立标注，暂停采用B。|
|山狼NE移动|A/B未形成明确对角腿交换，只建议A作有限移动姿势；B保留但不推荐组成循环。|
|棍僧SE/NE攻击起手、接触，4源帧|可作有限攻击关键姿势。SE接触的画面左脚支撑状态不确定，地面投影为空；NE两帧与SE起手可见双足接触代理完整。|
|山狼SE攻击起手、接触，2源帧|可作攻击姿势原型，但远后爪仅局部露出；不能宣称完整四爪支撑足迹通过，SE接触另有远前脚支撑疑问。|
|山狼NE攻击起手、接触，2源帧|可作攻击姿势原型。起手腹下爪局部遮挡／前足支撑不确定；接触两前爪腾空，仅后足作为当前可见支撑。|

20帧全部归档；接口推荐17帧供上述有限用途，另3帧的 `prototype_use` 明确标记暂缓／重复同相。不得静默换回旧侧视素材、将A/B存在当作步态通过，或把未知脚投影写成坐标。起手/接触只是视觉姿势标签，没有验证实际击中时序。

## 06接入接口

- 设计格：192×96、2:1菱形，顶点为(0,-48)/(96,0)/(0,48)/(-96,0)，以格心为原点。约30°是制作意图，AI原图没有经过实际相机标定。
- 两角色所有帧固定同一缩放 `0.34`，禁止逐帧缩放掩盖大小跳变。棍僧身体框约80.58–105.06宽、113.22–123.42高；狼约99.62–114.58宽、93.16–127.16高，单位设计像素。狼蓄势压低，故低于约96的目标下沿。实际整个角色（含棍/尾）另以帧图非透明像素为准。
- `image`指向已隔离透明PNG；不要将原图按五等分裁切，棍会跨分栏。`sample_rect=[x,y,w,h]`描述原图取样区域，区域内已排除邻帧；它不是可以不加分离掩码直接读取的原atlas矩形。使用独立帧最直接。
- 每帧以 `anchor_crop` 对齐格心：设计坐标 = (裁图像素坐标 − anchor_crop) × 0.34。锚点为人工摆放参考，未标定骨骼根或真实3D地面；连续播放仍需检查落脚漂移。
- SE镜像得到SW，NE镜像得到NW。使用连续边缘坐标时，镜像脚锚 `x'=图片宽−x`，y不变；设计坐标、足迹和视觉接触点统一 `x'=-x`。身体框镜像需交换左右界。
- `body_bbox_source/design`手工排除棍/尾的自然外伸，用于尺度检查；不能拿它裁整张图。`attack_contact_source/crop/design`为棍尖/狼嘴视觉点，不是攻击距离、碰撞盒或伤害数值。
- 建议从两角色待机和有限攻击姿势开始接入独立小样；有限移动姿势与失败循环须保留交接说明。动画时长、补间、命中时刻、运行接地与实际角色相互遮挡由06实现后再验，本包没有代定。
- 当前目录被 `.gdignore`隔离。由06按独立原型资源范围显式导入所需文件；本轮未改production、场景、程序或导出配置。

## 脚底证据与边界

人工标注的是**可见足端的二维包络与底边接触代理**，没有从二维图反推完整三维鞋底。脚ID按源图画面顺序，未强行认定遮挡时的解剖左右。静态待机要求双脚／四爪都能辨认，并检查每个包络顶点，不仅是格心。

菱格安全检查为 `|x|/96 + |y|/48 <= 0.90`。四个源待机最大值：棍僧SE 0.71188、NE 0.66937；狼SE 0.77208、NE 0.71542。镜像值相同，八个待机展示都在安全区。

全包7帧所有足端均被标为可见且接地；15帧的**当前已知支撑**完整，允许其他脚已明确腾空。这两个计数不同，均不表示20帧的全脚地面足迹通过。`partial/occluded/uncertain/swing`的 `ground_projection_design`保持null；支撑状态有疑问时整帧 `support_footprint_design`也为空，只保留已知部分的 `known_contact_proxy_hull_design`。

狼NE移动A/B、攻击起手/接触的**全部可见脚屏幕包络**分别为1.06604/1.02354/0.95625/1.29271，超出90%安全线，检查如实为false。其中含腾空／不确定脚，不能将屏幕高度当作地面落点，也不能宣称全帧全脚落格通过。已知接触代理全部在安全线内；隐藏脚的实际范围仍未知。后续若要求全姿势完整足迹或顺滑循环，这些是须另行解决的资产限制，不在本轮继续抽图。

## 来源、加工和验证

- 内置imagegen：每角色首图一次＋唯一一次定向修订，四原件原样保存在 `sources/`，原文件名、实际尺寸、SHA-256见manifest；没有新增生成。首图留历史，当前透明帧来自修订图。
- 身份参考为[獾类棍僧](../../concepts/guard_monk/nine_sols_v1/guard-monk-nine-sols-candidate.png)及[普通四足山狼](../../concepts/mountain_wolf/nine_sols_v1/mountain-wolf-nine-sols-candidate.png)，SHA也记入manifest。未将旧侧视角色直接当新斜俯视帧。
- 请求尺寸2500×1000未被工具严格采用；修订实际棍僧1983×793、狼1958×803，以真实像素标注。每图是5×2布局，但间隔与棍的跨列并不规则。
- `build_assets.py`只做离线机械拆帧、标注变换、合成预览及检查，没有绘制/补出身体或被遮挡的脚。使用现有Pillow与NumPy；用逐行连通域算法替代缺失的SciPy，无需安装新依赖。
- alpha≥8识别十个主体并保留周围两像素的原始抗锯齿，每个保留非透明像素的RGBA与源图逐字节相同。不保留的离散低alpha噪点最大alpha=6，alpha≥8丢弃数为0；四原件完全保留。透明PNG用于交付，灰底/格线只在预览里。
- 作者离线检查：4来源哈希、20透明帧路径/尺寸/取样范围、原RGBA保留、每角色统一缩放、脚锚与镜像、可见脚及接触代理边界。原错误的SciPy依赖已移除；预览API枚举拼写问题已修正。
- 独立只读技术复核：4原件与生成来源一致、20帧哈希/坐标/镜像正确、未知足点为空、步态失败保留，未发现阻塞字段错误。
- 独立只读视觉复核：1×五张预览中待机双脚/四爪、10%内线、四向镜像、棍尖/尾巴、灰底透明边缘通过；未见明显漏框/错框或残底。并确认以上换相、局部遮挡与腾空限制。
- 未完成：Godot运行、连续播放、打击连贯性、07独立游戏验收、真人观感。不能用本包检查替代这些验收。
