## 加工方法

用户明确允许使用本地脚本裁切、清底与打包。本批没有图像生成或重新绘制造型，原动作参考 PNG 未修改。

- 按每个角色的实际姿势位置逐项标注裁切框和必要的多边形，不按八格等分机械裁切。
- 对中性浅底做明度/色差分离，保留主连通身体、武器与衣摆；清理邻格碎片、独立地面阴影和游离残点。不给封闭洞自动填色，避免重现狐火样板的封闭残底。
- 在底部局部区域清除中性地面划痕；按人工标注的身体地面投影对齐，不把武器端点或全图外接框中心作为身体根节点。
- 每名角色的所有姿势采用同一个缩放倍率，不把受击、蹲伏和退场拉伸到待机高度。沿用此前尺寸建议：猎户 136、药灵 142、山雀 120、熊山君 164 像素待机外接框高度。
- 单帧统一 256×256，共同绘制锚点 `(128,218)`。图集按实际帧数横排；紧凑效果保持当前像素尺寸，使用 64×64 或 128×128 容器，不拉伸填满。
- 原图中的纸色与角色亮色局部接近，阈值清底不是无损分层算法；半透明雾气和贴合身体的细小笔触不能据此宣称与原稿逐像素等价。复核以当前棋盘尺寸可读性为准。

## 验证证据

- `validation.json`：4 个角色、22 张身体帧结构检查无失败。检查源文件哈希、RGBA、透明边界、图集与单帧逐像素一致、VFX 空帧和五动作映射。边界检查只证明成品留白，裁切完整性另外依靠原稿和预览人工对照。
- `godot-validation.json`：Godot 对 42 张运行时 PNG 的图像/纹理加载验证；不含审核图，不是完整战斗测试。
- `index.html`：按各角色 manifest 加载的独立预览，28/28 载入和动作映射检查通过。支持角色、动作、特效开关、深浅背景、慢速和时间定位。
- 已查看全部角色的深浅底六/五帧对照图；首轮发现的猎户普攻邻格碎片、角色脚底灰色阴影已在本批修改后复核。
- 浏览器逐项复核：猎户 0.160 秒普攻出手；药灵 0.080 秒有 1 枚独立药气；山雀 0.160 秒有 1 枚风刃，关闭特效后翅膀保留；熊山君受击姿势与主武器可辨。

## 接入约定与限制

- 图集帧宽固定 256；列数从 manifest 读取，不能把所有角色假定为六帧。
- 身体与同帧 VFX 使用同一个变换；Godot Sprite2D 若 `centered=false`，位置偏移为 `(-128,-218)`，若默认 `centered=true`，偏移为 `(0,-90)`，两种方式择一。
- 药灵与山雀发射独立投射物时关闭对应同帧投射物，避免重复。`aligned_center_trial` 为效果原位中心的试接入值，不能当作已确认命中点。飞行 0.20 秒、普攻 0.12+0.12/0.24 秒、受击 0.18 秒、退场保持 0.45 秒后 0.25 秒淡出均为样板建议节奏，不改玩法数值。
- 武器仍属于身体帧；部分贴合武器或身体的挥击笔触无法无损拆出，只有明确在轮廓外的效果被分离。
- 熊山君受击的后仰幅度、碎山棒握持关系及贴在肩部的冲击笔触沿用已允许的 Demo 参考，未重画；不能据此声称正式受击动画已解决。
- 山雀单枚风刃只作 Demo 普攻占位，不确认后续技能风刃/箭矢语义；本批不制作伙伴、召唤物或技能专属动作。
- 深色衣物在暗底的内部细节仍偏沉。缩小后的细节适合当前 Demo 棋盘尺寸，不适合放大作为高清角色展示。
- 源姿势本身的重心和轮廓差异仍会在切帧时跳变；人工地面锚点是接入起点，实际移动、转向及密集阵型仍需 06 调试与验收。

## 复现

在仓库根目录，用包含 Pillow 和 NumPy 的 Python 运行：

```text
python godot-demo/art/production/tools/build_four_role_demo.py
python godot-demo/art/production/tools/verify_four_role_demo.py
godot --headless --path godot-demo --script res://art/reviews/four-role-demo/verify_resources.gd
```

预览可直接双击本目录的 `index.html` 打开，无需启动服务。请保留完整仓库目录结构（页面旁的 `preview-data.js` 及 `../../production/` 中的图片）。HTTP 访问也兼容。
