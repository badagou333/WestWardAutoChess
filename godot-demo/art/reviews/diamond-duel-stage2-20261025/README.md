# D002 菱形格双角色 Demo — 阶段二实机渲染复核

更新时间：2026-10-25。归属：`05｜美术 / 角色 / UI`。对应 `D-20261018-002` 第二阶段（07 已出独立技术限定通过，无生产必修）。

本目录只放**本轮实际窗口渲染**的关键帧与量测结论，用于回答三件事：退场淡出是否真实存在、每格 0.50 秒移动的连续观感、以及在更小窗口下角色是否仍明显归属单格。不代替 07 技术验收、不代替负责人真人体验。

## 采集方式（真实窗口，非 headless）

- 专用窗口 `--path godot-demo --script res://tests/<临时采集脚本> -- --output=… --width=… --height=…`，窗口标题 `D002 菱格对打 · 阶段二实机复核`；引擎 4.7.2，渲染 OpenGL 4.1 Metal（Apple M1），音频 Dummy，未操作任何用户已有 Godot/Spine 窗口，未改系统 DPI、未做全屏采集或 OS 级鼠标。
- 与本批已提交的 `tests/diamond_duel_capture.gd` 同源做法：`root.get_texture().get_image()` 保存真实 Viewport 帧。
- **可复现性**：用原脚本按原条件重跑一次，5 张既有证据（`tests/board-trial-runtime/diamond-duel-20261019/actual-window/`）**逐字节相同（SHA 全等）**，说明该证据确为确定性真实渲染。
- 采集脚本为本轮临时工具，**未提交**（不新增生产/测试入口）。若需复跑：在战斗结束后让主循环跑起来（`game.set_process(true)`，等价于真实 `_process` 的 RESULT 分支），再按 `wolf.presentation.pose_time` 取点；旧脚本 `game.set_process(false)` 会让 RESULT 阶段的 `tick_visual` 完全停住，见下文。

## 一、退场淡出：真实存在，之前的「05-result 未淡出」是采集器假象

- 棍僧/山狼的受击与死亡帧未制作（已知限制），退场 = `retreat` 姿势下 alpha 线性淡出。
- 实测时间轴（`t=15.55` 阵亡）：**保持 0.35 秒 + 淡出 0.30 秒**，到 0.65 秒完全消失并由敌人节点自释放（`scripts/enemy.gd` 的 `if dead and presentation.visual_alpha <= 0: queue_free()`），画面无残留。

| 记录帧 | 狼 pose_time | 狼 alpha | 画面 |
|---|---|---|---|
| `20-death-000` | 0.000 | 1.000 | 刚阵亡，仍满不透明（旧 05-result 就等于这一帧） |
| `21-fade-350` | 0.382 | 0.894 | 刚开始淡出 |
| `21-fade-450` → [`fade-mid-1440.png`](fade-mid-1440.png) | 0.474 | 0.585 | 半透明，影子同步变淡 |
| `21-fade-550` | 0.576 | 0.246 | 接近消失 |
| `22-fade-end` → [`fade-end-1440.png`](fade-end-1440.png) | — | 节点已释放 | 狼完全消失，棍僧已回 `idle`，结果面板「已退场 / 棍僧获胜」 |

- **更正第一阶段结论**：上一轮 `05-result.png` 停在 alpha=1、棍僧定格在 `attack_contact`，原因是采集脚本一开始就 `game.set_process(false)`，而 `step()` 在 `phase!=BATTLE` 时直接 return，于是 RESULT 阶段只靠 `_process` 推进的表现时钟完全不前进。真实窗口里（`_process` 正常）淡出照常播放，棍僧也会回到待机。**这不是游戏的视觉缺陷，是取证脚本的口径问题**；建议 06 在正式采集脚本里于 RESULT 阶段恢复推进（或补一帧 pose_time≈0.45 的退场图），否则证据会继续显示一个游戏里不会出现的定格状态。
- 淡出本身没有颜色偏移、没有突然跳变、影子跟着一起淡（`diamond_duel_stage.gd` 影子的 opacity 乘 `visual_alpha`）。唯一可预期的是"跳跃"：阵亡当帧由 `wolf_ne_attack_contact`（前爪腾空的扑咬）直接切到 `wolf_ne_idle` 再淡出——这是"无受击/死亡帧"的既定后果，不另记缺陷。

## 二、连续移动：0.50 秒/格、线性、无漂移；观感是"两姿势平移"

7 个采样点覆盖第一整格（棍僧 (−3,0)→(−2,0)，设计格心 (672,444)→(768,492)）：

| move.time | 棍僧脚点（设计px） | 狼脚点 | 棍僧帧 |
|---|---|---|---|
| 0.025 | 676.8, 446.4 | 1243.2, 729.6 | `monk_se_move_a` |
| 0.108 | 692.8, 454.4 | 1227.2, 721.6 | `move_a` |
| 0.208 | 712.0, 464.0 | 1208.0, 712.0 | `move_a` |
| 0.283 | 726.4, 471.2 | 1193.6, 704.8 | `monk_se_move_b`（≈50% 换相） |
| 0.367 | 742.4, 479.2 | 1177.6, 696.8 | `move_b` |
| 0.442 | 756.8, 486.4 | 1163.2, 689.6 | `move_b` |
| 0.483 | 764.8, 490.4 | 1155.2, 685.6 | `move_b` |

- 位置与时钟严格线性：0.208s → 41.7%，速度 192 设计px/s（=96 设计px ÷ 0.50s），x/y 同时推进，**没有任何缓动、竖直弹跳或落点补偿**。
- 起停：出兵前与落格后脚点都精确等于格心（如 `12-attack-start` 脚点 (960,588) = (0,0) 格心）；0.483s 时距格心 3.2px，正好是最后 1/120 秒应走的距离，不是吸附跳变。
- 姿势：棍僧 SE 有 A/B 两相，在 50% 处换一次；**狼全程只有 `wolf_ne_move_a` 一相**（见 [`move-a-0417-1440.png`](move-a-0417-1440.png) 与 [`move-b-0733-1440.png`](move-b-0733-1440.png)）。所以视觉上是"棋子整体平移 + 一次换腿"的滑步，而不是循环步态——与素材交接的限制一致，不属新缺陷；但也说明"每格 0.50 秒"目前主要靠位移读出来，不靠步频。
- 移动中角色跨在共享边两侧属正常（逻辑格要到最后一步才提交），格线仍可辨。

## 三、实机尺度与可读性（1440×810 / 1280×720 / 1024×576）

三种窗口都跑了同一段（布置、整格移动 7 采样、起手、接触、阵亡+淡出），结论一致：

- 项目逻辑视口 1920×1080，`canvas_items` 拉伸：1440 窗口=0.75、1280=0.667、1024=0.533，全部等比缩放，**没有重排或裁切**。
- 角色仍明显归属单格：格 192×96 设计 / 144×72 屏，角色外廓约 104×90 屏（0.72 格宽、1.25 格高）；1024 下约 55×48 屏，仍在各自格心，格线可辨。
- 顶栏数字在 1024 下仍清楚（"护寺棍僧 HP 310 / 310""山狼 HP 180 / 180""对打时间 1.60 秒"）。侧栏与底部说明等比缩小，1024 下为次要文本，可读但已接近下限。
- 1024 的起手帧见 [`windup-1024x576.png`](windup-1024x576.png)。
- 阶段一担心的"狼起手腾空前爪压进棍僧格 10–12px"：**1x 下不构成误读**。1440 与 1024 的整图里，读者看到的是"狼压低身体扑向对手"，加上影子仍在狼自己格心，不会读成"踩在棍僧格"；只有放大到 3x 以上才明显。维持"素材固有、不必修"。

## 四、满血血条：是显式设计，不是漏绘

`scripts/presentation/board_depth_hud.gd` 的绘制条件为 `game.phase==DEPLOY or actor.health<actor.max_health or chosen`。即：布置阶段双方都显示；战中只有**受过伤**的一方显示（本例 04 起只有棍僧的绿条）；阵亡当帧因 `health<=0` 直接不画。实机画面与代码条件一致（起手帧双满血 → 两条都没有）。这是可读性取舍，本轮按"设计"处理，不改；如果负责人希望交战时一直能看到双方血量，那是另一次观感调整（不再是"缺陷修复"）。

## 五、棍僧地面影子（23×6 设计半径）：可延后，不必修

- 影子是运行期绘制：`diamond_duel_stage.gd` 里按角色写死 `Vector2(23,6)`（棍僧）/`Vector2(34,8)`（狼），与脚点同锚。
- 1x 实测：影子只是两脚之间一块很淡的暗斑（alpha 0.16 + 5 层柔边），**在 1440/1024 的实际观感里几乎注意不到**，也不影响"属不属于这一格"的判断；放大 4x 以上才看出影子比 73px 的站距窄。
- 结论：**可延后**。若以后做观感统一，把 `(23,6)` 调到约 `(34,7)`（或直接按已知接触代理宽度算）即可，纯运行期常数，不涉及素材与 0.34 缩放。
